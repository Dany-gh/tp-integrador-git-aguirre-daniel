10. Comandos mínimos que deben aparecer en el trabajo

El trabajo deberá evidenciar el uso de los siguientes comandos principales:

git init
git status
git add
git commit
git log --oneline
git remote add origin
git remote -v
git push
git branch
git switch
git merge
git pull
También se aceptará el uso de: git checkout
en lugar de git switch, siempre que el participante lo indique en el archivo ENTREGA.md.
11. Desarrollo mínimo esperado

El participante deberá realizar las siguientes acciones.

11.1. Crear un repositorio local

Crear una carpeta de trabajo e inicializar Git.

Comandos esperados: git init git status

Cuando hago git init la rama principal le llama master y yo le quiero cambiar el nombre a main para eso hago.

git branch -m master main

y ahora hago git branch para ver en que rama estoy. Ahora estoy en la rama main.

Ahora vamos a pasar los archivos al área de stage.
Usando add .
git add .

Ahora todas las filas y carpetas están en verde y pasaron del area de trabajo al área de stage.

11.2. Crear la estructura inicial del proyecto

El repositorio deberá incluir:

  • README.md;
  • ENTREGA.md;
  • una carpeta para el proyecto;
  • al menos un archivo dentro de esa carpeta.
Ejemplo:
proyecto/
├── index.html
└── styles.css

Ya está todo esto creado.

11.3. Registrar cambios mediante commits

El trabajo deberá tener como mínimo cinco commits. Los mensajes de commit deben ser claros y representar cambios concretos.

Ejemplos adecuados:

git commit -m "Agregar estructura inicial del proyecto"
git commit -m "Completar descripción del proyecto en README"
git commit -m "Agregar archivos principales de la landing"
git commit -m "Crear rama para mejorar documentación"
git commit -m "Actualizar entrega con enlaces del repositorio"
No se consideran buenas prácticas mensajes genéricos como:
git commit -m "cambios"
git commit -m "cosas"
git commit -m "final"

Vamos a crear el primer commit.
git commit -m "Tiene la estructura inicial. Los archivos *.md sin datos, y los dos archivos del proyecto vacios"
Se realizo con éxito el commit
Hacemos
git status
nothing to commit, working tree clean
hacemos
git log
Me muestra el primer commit.

11.4. Publicar el repositorio en GitHub

El participante deberá crear un repositorio público en GitHub y conectarlo con el repositorio local.
Comandos esperados:
git remote add origin URL_DEL_REPOSITORIO
git remote -v
git push -u origin main
Si la rama principal tiene otro nombre, deberá aclararlo en ENTREGA.md.
git remote add origin https://github.com/Dany-gh/tp-integrador-git-aguirre-daniel.git
Revisamos con
git remote -v si está bien la dirección o url.
Hacemos el push (subir a remoto lo de local)

11.5. Crear una issue en GitHub

El participante deberá crear al menos una issue relacionada con una mejora, tarea o corrección del proyecto.


La issue deberá tener:
  • título claro;
  • breve descripción;
  • relación con alguna mejora concreta del repositorio.
El enlace a la issue deberá incluirse en ENTREGA.md.
https://github.com/Dany-gh/tp-integrador-git-aguirre-daniel/issues/1
11.6. Crear una rama de trabajo

El participante deberá crear al menos una rama de trabajo para resolver la issue o realizar una mejora. Comandos esperados:

git branch
git switch -c mejora-readme
También puede utilizar:
git checkout -b mejora-readme
Usamos:
git switch -c mejoras_solicitadas
11.7. Realizar cambios en la rama

En la rama creada, el participante deberá modificar al menos un archivo del proyecto o de la documentación.

Luego deberá registrar el cambio:
git status
git add .
git commit -m "Mejorar documentación del proyecto"
git push -u origin mejoras_solicitada
